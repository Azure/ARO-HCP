# Fixes for Management Clusters

Any changes to management clusters that are needed
but can't be applied using AKS configuration
go here.
Ideally anything here is treated as temporary
and always ends up getting upstreamed.

## Proportional Kubelet Reservations

The kubelet DaemonSet intentionally migrates AKS `--kube-reserved` to
`--system-reserved` as the existing scale-stability workaround (ARO-13357).
It also updates nodes already using the legacy fixed system reservation.
CPU and memory scale independently from the 32-vCPU, 256-GiB baseline:

- CPU: `ceil(host online CPUs * 3000 / 32)` millicores.
- Memory: `ceil(host MemTotal KiB * 7550 / (256 * 1024 * 1024))` MiB.
- PID: `1000`, unchanged.

Capacity is read on the host through `nsenter`, using
`getconf _NPROCESSORS_ONLN` and `/proc/meminfo`, not container limits or node
allocatable. `MemTotal` is OS-visible RAM, slightly less than nominal SKU RAM;
a nominal 256-GiB node can therefore reserve slightly less than 7550 MiB.
Exact 32-vCPU/256-GiB inputs give 3000m/7550Mi; 16-vCPU/64-GiB inputs give
1500m/1888Mi; 8-vCPU/32-GiB inputs give 750m/944Mi. No SKU configuration,
including production SKUs, is changed here.

The edit requires `/etc/default/kubelet` to contain single-line environment
assignments, blank lines or comments, with no repeated assignments and exactly
one reservation flag. Unquoted values containing spaces, empty values, and
single- and double-quoted assignments (including a reservation as the final
argument) are supported. This follows the systemd EnvironmentFile generated by
[AgentBaker's ensureKubelet](https://github.com/Azure/AgentBaker/blob/bb4a739f9699efb521f7b2c1bf8f063dc669606e/parts/linux/cloud-init/artifacts/cse_config_kubelet.sh#L247-L279),
not shell assignment syntax. In particular, unquoted eviction thresholds with
`<` and `%` are preserved, not interpreted as shell operators. Unsupported
nested quoting, escapes, expansion in the reservation assignment,
missing/duplicate flags, duplicate reservation keys,
and invalid capacity fail without changing the file or restarting kubelet.
Unrelated flags and reservation resources such as `ephemeral-storage` are
preserved. The host file is never sourced, evaluated, or shell-syntax checked.

Before atomically replacing changed configuration (preserving permissions and
ownership), the script creates the persistent, empty, mode-0600 host marker
`/etc/default/kubelet.system-reserved-restart-pending`. It then reloads systemd,
restarts kubelet, and waits for `http://127.0.0.1:10248/healthz` using host curl
with bounded requests and a 120-second retry window. Only success clears the
marker. Reload, restart or health failures leave it for the next attempt, even
when the file already matches. Interruption after creating the marker but
before replacing the file may cause an extra restart, deliberately preferring
recovery over silently skipping one. Unknown marker contents, permissions,
ownership, symlinks, or hard links are rejected rather than overwritten.
Unchanged configuration is not rewritten; without a pending marker it is not
reloaded or restarted, but its health is still checked.

Rollout uses `maxUnavailable: 25%` and `maxSurge: 0`, with a 30-second
`minReadySeconds` stabilization interval. Fully serial rollout
(`maxUnavailable: 1`) scaled linearly with pool size and blew the Helm
client-wait budget on mgmt clusters at prod scale (up to 42 worker nodes
× ~40-70s per node); 25% bounds concurrent kubelet restarts to ~a quarter
of the pool so rollout finishes within a few waves without letting the
whole pool restart at once. The privileged init container must
finish applying the fixes before the main container starts. Its readiness
probe checks local kubelet HTTP responsiveness. The kubelet health endpoint
is only a ping: it does not establish Node Ready, runtime/network recovery,
or publication of updated allocatable capacity. A failed init or HTTP probe
holds rollout, but these checks are not a drain or a guarantee of serialized
node recovery. Canary this change and check node readiness and allocatable
capacity before wider rollout. No live-host validation is performed by the
unit tests.

Security review: this privileged, host-PID DaemonSet runs a shell and utilities
on the host via `nsenter`. Changes to the embedded chart script require the
same CI/security review as changes to the manifest. Behavioral tests in
`tooling/helmtest/testrunner/system_reserved_test.go` render the chart and use
sandbox paths and command stubs; they never enter host namespaces or restart
real services.

The host script is fail-fast. The legacy node-exporter adjustment is skipped
when `/usr/local/bin/node-exporter-startup.sh` is absent, as on newer AKS images;
it must not block successful kubelet initialization. When the script exists,
adjustment failures still fail initialization. Host curl must support `--retry-all-errors`
and kubelet's localhost health endpoint must be enabled; otherwise rollout
stops rather than reporting readiness without a health check.
