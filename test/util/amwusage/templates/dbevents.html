How these rates compare (not exact event accounting)

A platform timestamp t represents [t, t+60). Its minute maximum is weighted by the overlap with the exact run window, clipping the first and last buckets. The reference requires every covered minute to have valid nonnegative usage and a positive valid limit. Missing, invalid, ambiguous or off-grain measurements make the whole-run mean unavailable, rather than averaging only observed minutes.

Stored samples cover (start, end] by sample timestamp, not AMW receipt time, and divide by the full run duration including partial minutes. Weighting bucket maxima does not recover exact received totals. Timing, storage, drops and unresolved sources can leave a signed reconciliation gap; no equality is forced. Samples are not application-counter increments or histogram observations.

Namespace identity, coverage and comparisons

Key: workspace + cluster + namespace + hostedcontrolplane. Job/source groups are additive; underlay namespaces are never collapsed into HCP names. (absent) and (empty) are distinct identities; an absent HCP label is shared or unattributed, not verified ownership.

Each period uses only complete, validated ranking parents. Partial leaves are included only in the rate reconciliation above, not namespace subtotals. A completed empty parent contributes zero; an unknown parent does not. Before and end can cover different metrics; net is unavailable unless both periods use the same accepted metric set. The preceding 12 hours are standing inventory, not a verified quiet baseline or causal run growth.

End shares use each workspace's ActiveTimeSeries end reference. Sample-rate shares use its time-weighted mean of AMW minute maxima, an approximate rate reference, never a received sample total. All remaining metrics and namespaces are exactly added before display truncation; unresolved parents remain an unknown-source gap.
